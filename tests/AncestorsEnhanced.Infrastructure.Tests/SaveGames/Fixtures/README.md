# Save-game fixture policy

This directory intentionally contains no real Ancestors save files.

The shipping application currently uses saves only for local checkpoint creation, validation, comparison, and restore. It does not expose the former 0.9 save-value cheats and does not patch neuronal energy, needs, health, or clan data.

## What automated tests cover

Synthetic saves and generated byte fixtures cover:

- Snappy block validation before a checkpoint is published or restored
- bounded reads and canonical slot/checkpoint paths
- temporary-directory publication and manifest/hash validation
- checkpoint deduplication and retention
- compare-and-swap restore with a PreRestore safety checkpoint
- interrupted-restore journal recovery
- preservation of unexpected or externally changed live saves
- the standalone read-only tagged-property schema analyzer

These tests prove the code paths and byte-safety invariants they exercise. They do not prove that a restored save loads successfully in the game.

## External release checks

A real in-game checkpoint test remains external to this repository:

1. Create a manual checkpoint from a supported live slot.
2. Advance or otherwise change the save in-game.
3. Close Ancestors and restore the checkpoint through AEC.
4. Confirm that the PreRestore checkpoint exists.
5. Start Ancestors and verify the restored lineage loads and matches the intended progress.
6. Confirm that restoring the PreRestore checkpoint returns to the newer state.
7. Repeat under the supported cloud/Proton combinations being released.

Never commit a personal save merely to make this directory non-empty. Any future real fixture must be explicitly authorised, anonymised, legally redistributable, documented with its game build, and reviewed for identifiers before it enters the repository.
